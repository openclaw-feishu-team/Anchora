# benchmark_sry 速览

## 是什么

围绕 **飞书项目决策记忆**（`memory.py` 等）的**独立基准测试**目录，与根目录原 `benchmark.py` 解耦。用统一 Runner 把 JSON 用例喂给真实存储与检索逻辑，按痛点打分，输出 **JSON + Markdown 报告**。

## 这里有什么、在干什么

| 部分 | 作用 |
|------|------|
| `run_benchmark_sry.py` | 加载用例、执行、断言、汇总指标、写 `outputs/` |
| `cases/` | 五类痛点各一组 `*_cases.json`（决策沉没、碎片、上下文失效、矛盾更新、决策重复） |
| `cases_new/` | 扩充版题库（与 `cases/` 并存，用于迭代对比） |
| `docs/` | 字段说明（`BENCHMARK_CASES_REFERENCE.md`）、大白话说明（`benchmark解释版.md`）、新旧题库对比与丢分分析等 |
| `outputs/` | 每次运行的报告快照（**运行时生成**，可按需是否纳入版本库） |

运行入口见根目录 `README.md`。测试数据默认挂 **`project` 前缀 `_benchmark_sry_`**，Runner 会清理，避免污染业务库。

## 结果如何（概括）

- **报告**：`outputs/` 下有多份带时间戳的报告，可按文件名区分题库版本（如 `case_new`、`cases_old`、`no-eff` 等）。
- **量级**：当前 README 口径为 **100 条用例**（5 痛点 × 每条若干扩展）；某次全量跑（100 条、`no-eff`）文档中记载 **得分率约 72.57%**，整题通过约半数场景，其余多为「部分通过」。
- **短板（文档归纳）**：主要集中在 **检索排位（rank）**、**矛盾/上下文下的 supersede（覆盖链）**、**负例仍被 recall 召回**；抗干扰类易出现锚点被干扰决策挤到后排。
- **`cases_new` 单次示例**（2026-05-04）：81 条跑批次显示通过率更低、若干核心指标偏弱——说明**题库加码或策略调整后**，系统尚未对齐新门槛，需对照该次报告逐项优化。

更细的丢分原因见 `docs/BENCHMARK_LOSS_ANALYSIS_2026-05-04_no-eff.md` 等；分用例明细以具体 `outputs/*.md` 为准。
